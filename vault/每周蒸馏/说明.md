# 每周蒸馏

系统总机制见 [[20 萌芽Wiki/04 分析与对比/萌芽知识库运行机制|萌芽知识库运行机制]]；本页只说明每周执行与结转规则。

每周先看 [[_系统/模块配置|模块配置]]、[[项目注册表]]、[[个人成长总览]] 和 [[项目能力矩阵]]。只检查状态为“进行中”的项目和已经启用的模块；没有真实变化时写“无”，不要为了均衡而制造任务。

每周五的 Codex 自动化报告保存在这里，文件名使用：

`YYYY-MM-DD-每周蒸馏.md`

报告用于回答：本周新增了什么、哪些知识进入了使用、哪些结果已经回填、哪些认识被修正，以及下周唯一优先闭环是什么。

## 结转机制

每次报告正文的最后一节固定为“周结转清单”，包含六项：

1. 本周真正完成了什么；
2. 哪些认识获得新证据；
3. 哪些任务继续结转；
4. 哪些内容应停止维护；
5. 下周唯一优先行动；
6. 新产生的种子。

下一次自动蒸馏先读取上一期结转清单，逐项核对“上周唯一优先行动”。每项必须归为**完成 / 延期 / 取消 / 无法判断**，附本周证据；没有答卷、成绩或实际交付时不能写完成。延期要写阻碍及最晚复查日，取消要写需求变化与原任务去向，无法判断要写缺什么证据。然后才选本周的新唯一行动，避免每周重复生成相同建议。历史周报不回写。

课程模块启用时，按 [[学习笔记/课程资料流水线|课程资料流水线]] 核对本期进行中课程的处理记录。周报引用真实变化与待办，不重新运行全部课程阶段。

课程、作业等技能的产出先看 [[_系统/交接/说明|交接记录]]，不再重读已处理的正文；用户自己写的内容不经过交接，仍按改动清单逐个读。

判定上期行动时，先看交接记录里技能名为“本人结果”的行，它们来自 [[10 原始种子/00 收件箱/本人结果/说明|本人结果收件箱]]。周报开头在一句话判断之后列出“需要你投放的”，最多 3 条，每条写明缺的具体是哪一样，例如“A1：学校教学平台 提交页截图”。上期已经列过且没有变化的不重复列；没有缺口时写“无”。

[[项目能力矩阵#证据记录|项目能力矩阵的证据记录]]本周有新行时，据此更新矩阵“当前项目”表中对应项目的“当前证据”“证据状态”和“下一次验证”；没有新行就不动那张表。

自我剖析启用时，查看 `自我剖析/04 目标/` 各页的 `下次复查` 和 `截止`：已到期或没有填复查日的，每期只在“需要你投放的”里提一个，请本人更新现状或填一个复查日；不替本人填写现状、日期或结论。

### 判定规则

- **完成**：必须有结果或验收证据，只有计划、阅读或空模板不算完成。
- **继续结转**：必须写明阻碍、下一步和最晚复查日期；连续三周无进展时必须决定继续或停止。
- **停止维护**：停止主动投入但保留历史文件，不自动删除内容。
- **唯一优先行动**：只能有一个可在一周内验收的行动，不能把多个任务拼在一起。
- **新种子**：必须指向本周来源；AI 推断标为 E0 或待核。

模块配置中关闭的模块必须在读取前排除：不扫描其目录、不在周报中引用或评价其内容，包括命理。记录 YAML 的 AI 权限字段只是声明，自动化还须执行读取过滤。

## 播客迭代

播客纳入每周蒸馏，但不按文件数量判断进度。每周只记录真实发生的选题、稿件、制作、发布、数据回填和复盘变化，并检查上一期结论是否用于下一期。播放量验证选题或表达效果，不证明观点正确。具体见 [[播客/迭代说明]]。
