# 作业与代码项目工作流

所有课程文字作业按[coursework-writing](<~/.codex/skills/coursework-writing/SKILL.md>)执行，包括初稿、其他模型稿件的改写和交付前审阅。要求与格式、引用与链接、润色、标点、信号审计、检查强度和核验表都以该技能为准，本页不重复。

作业正文与提交内容默认英文，交流解释可用中文；原始课程材料保持只读。

装了子代理时，整篇成稿或交付前审阅完成后，派 `coursework-reviewer` 独立复核（只读，不改稿，见 [[_系统/技能地图#子代理|技能地图]]）。把成稿、题目、rubric 和来源路径交给它，按它报告的“必须改”逐项处理，处理后的终稿再复核一次。复核结果不代替本人确认和提交。

## 本地写作信号自检（可选）

如果你在本机装了离线的文本评分工具（例如基于 Binoculars 方法、本地小模型运行、不联网不上传的脚本），可以把它作为写作诊断的补充。模板不附带这类工具，需要自备，用法和校准数据写在工具自己的 README 里。

- **什么时候用**：整篇成稿后、交付前，和技能里的信号审计并列做；局部修改不跑。正文有实质改动后，对终稿重跑一次。
- **写进核验表**：放在“写作信号”一行，写成“本机工具参考分数”：文件名、运行时间、标记段数/正文段数、报告路径。不写成 AI 率、AI 生成百分比、Turnitin 预测或作者证明。
- **怎么处理标记段**：只用来找模板化的段落，由本人按自己的理解重写，事实、引用和术语保持不变。不为压低分数反复改写，不故意制造错误，也不把它当成让 AI 产物躲过检测的工具。
- **局限**：这类工具漏检和误标都常见，人写的文字也会被标记。0 不代表本人写的，被标记也不代表一定是 AI。分数和 Turnitin 等平台无关，不能证明作者身份或本人掌握。先在自己确定是本人写的文字上校准，知道误标率再用。

## 代码类任务的技能

| 任务 | 技能 | 验收重点 |
| --- | --- | --- |
| 编写有可测试行为的功能 | `tdd` | 先验证失败，再实现通过；按技能确认测试接口 |
| 修复代码问题 | `diagnosing-bugs` | 可复现、原因有证据、修复有回归验证 |
| 设计模块与接口 | `codebase-design` | 接口清晰，复杂度适合课程任务 |
| 代码交付前检查 | `code-review` | 符合题目、项目规范，结果有验证 |

含代码时沿用现有项目结构和技术栈，运行相关代码与测试，保留真实命令、结果和未验证项，并能解释关键实现与边界。skills 位于 `~/.codex/skills/<技能名>/SKILL.md`，先实际读取再执行，缺失时明确说明。

`code-review` 正文要求的 `/setup-matt-pocock-skills` 和 issue tracker 配置已随工程编排技能移出，课程作业不适用：按题目、rubric 和项目自身规范审查，跳过该步并在记录中写明。

## 边界

- 作业计划、草稿和证据保存在对应作业/项目目录。实际代码沿用用户指定代码仓库；未指定且位置影响大时再询问。另一个代码仓库遵守其自身 AGENTS.md，不把整个笔记库初始化成代码仓库。
- 安装技能不等于授权提交代码、推送、发布、创建远程 issue 或向外部服务发送课程材料。

## 提交与学习结果分开记录

每次任务保留本人贡献和 AI 协助范围。文件完成、核验通过、本人已提交是不同状态；没有提交凭证或本人确认，不写“已提交”。独立解释、代码运行或答题结果可作为学习证据，AI 草稿和模板不能证明本人掌握。

复习采用单独流程“范围 → 自测 → 错因 → 训练 → 复测”，不套用作业提交状态。每次学习至少留下一个可检查结果，如本人答卷、独立解释或代码运行记录。详见 [[学习笔记/学习反馈与复测规则]]。
