# 课程资料流水线

课程资料的收集、整理、课堂讲解、日程、预习和复习统一从这里分流。先完成前置检查，再按触发条件读取对应细则；一次任务只执行需要的阶段。课程内容和执行状态继续保存在原位置。

[[学习笔记/00 学习首页|学习首页]]。每位学习者的入口放在 `学习笔记/<学习者>学习资料/`。

## 前置检查

1. 先遵守 [[_系统/共同规则|共同规则]]，读取 [[_系统/模块配置|模块配置]]。课程学习关闭时停止课程读取和网站访问；Anki 关闭时跳过卡片阶段。
2. 读取 `_系统/学习资料归属.json`，按学习者进入对应首页，核对学期、课程状态和授权范围。只为本学期“进行中”的课程安排主动维护；归属、学期或课程不明时先列待确认，不从文件名猜测。
3. 读取本次涉及的课程主页、课程计划和最近处理记录，确定允许读取及拟修改的页面。仅查看与本次触发有关的来源，保持两人的个人任务、答卷和学习结果分开。
4. 同一批次指定一个写入者，日检、周检和手动操作复用既有处理状态。发布前复核目标页面是否被别人修改；发现变化先重新读取，不能覆盖新内容。这是维护约定，不代表两个 AI 入口已具备共享的技术锁。

已结课课程保留历史资料和来源。用户明确要求回顾旧课时按指定范围处理，不把它重新列入本学期行动，也不据此推断成绩、掌握或提交情况。

## 按触发条件执行

| 触发条件 | 读取的细则 | 本阶段留下的结果 |
| --- | --- | --- |
| 到达现有网站检查时间，或用户要求收集已授权课程资料 | [[学习笔记/学校网站自动检查|学校网站自动检查]] | 核验学习者、课程与学期；增量取得原件和通知，登记实际覆盖范围与失败项目 |
| 有新增、变化或已下载但尚未整理的本地来源 | [[学习笔记/课程资料周检-Prompt|课程资料整理细则]] | 更新课程唯一正文、作业执行卡、资料缺口与来源记录 |
| 用户交付课堂录音、转写或图片 | [[学习笔记/课堂录音整理流程|课堂录音与图片流程]] | 原件副本、时间戳转写、中文讲解及课件对照；装了 `class-recording-to-obsidian` 技能时按它处理 |
| 课表、停补课、考核时间或提交期限有可靠新增或变化 | [[学习笔记/课程日程整理-Prompt|日程整理细则]] | 更新受影响的日程及新版 ICS；正式、推定、建议分开 |
| 新教学周进入预习窗口，或该周资料、考核范围变化 | [[学习笔记/每周双语预习与考核标注|双语预习规则]] | 在该周首节课前 7 天检查预习需要；中英对照、范围有据、答案置末 |
| 用户要求复习或真题对应，或本次考核范围更新需要调整已有题答页 | [[学习笔记/考点对应真题整理-Prompt|考点与真题规则]] | 以本学期范围对应题目，保留原卷、题号、答案来源与待核项 |
| Anki 已启用，且本次需要新增或更新学习卡片 | [[anki/考试复习/README#每门课程的 Anki 模板选择流程|Anki 模板选择流程]] | 按目标选型并核验样卡；导入、设备验证与本人复习分别记录 |
| 本人提交了实际答卷、代码结果或学习反馈，或 `10 原始种子/00 收件箱/本人结果/` 有新增文件或随手记新行（每次日检都查看） | [[学习笔记/学习反馈与复测规则|学习反馈与复测规则]] | 保留本人原始结果，按证据类型更新提交状态，记录错因、训练与延迟复测，不用 AI 产物代替能力证据 |
| 用户要求课程周检 | [[学习笔记/课程资料周检-Prompt|课程周检]] | 核对本期进行中课程，复用日检结果，只补未处理来源、预习窗口及变化；给出一项可验收的后续行动 |
| 用户要求建立新学期课程或启用周检 | [[学习笔记/课程资料自动整理-使用说明|建课与启用说明]] | 建立课程主页和课程计划，未知日期和占比标记待公布 |

纯翻译只处理用户指定内容。没有归档要求时，不因收到一张图片就启动整套流程。课程资料、音频和私人记录的外发授权继续逐项核对；默认沿用已确认的本地处理方式。

## 读取课件与文档

PDF、PPT 和 Word 课件先用本地工具抽取文字再读。只有图表、公式截图、扫描页，或抽取结果为空、乱码的页面才看页面图像。每页只看一次：把看到的内容连同页码写进对应笔记，之后从笔记读取，不重复看图。抽取失败或 OCR 得到的内容标明可能有误。

## 去重与正文归属

- 先核对已有来源路径、哈希和处理状态。同一内容可以复用整理成果，但仍保留各学习者和网站的来源关联；同名更新另存版本。
- “已下载”只完成收集阶段。来源尚未整理时继续处理，不能因为哈希已登记就跳过全部后续阶段。失败保留重试状态，成功写回并回读后才推进对应阶段。
- 预习按学习者、学期、课程、周次、来源版本和范围版本识别。同一周无变化不重建；没有新文件时仍检查新周窗口。
- 课程主页负责导航，课程计划维护安排与考核范围，课程主笔记维护稳定知识，作业页维护要求和提交过程，题答页保存题目与答案。每日计划、周报与首页引用这些正文，不再复制维护。
- 通知或范围变化先更新课程计划，再同步受影响的日程、预习和题答页；未知日期或组别保持待核。

## 状态文件各自负责什么

| 现有文件 | 负责的状态 |
| --- | --- |
| `_系统/学校网站处理状态.json` | 学校教学平台 资料与通知的采集、入箱、来源覆盖和整理关联 |
| `_系统/Teams课程处理状态.json` | Teams 消息、附件、课程映射、覆盖缺口和整理关联 |
| `_系统/课程日程处理状态.json` | 本地来源处理、日程产物、周预习版本、已通知问题及日历导入凭据 |
| `_系统/学习资料归属.json` | 学习者入口与资料路由 |
| `_系统/<学期><学习者>个人任务状态.json` | 该学习者本学期任务准备、本人掌握和提交证据 |

继续使用这些文件的既有字段和版本，本轮不迁移或合并 JSON。下载、整理、本人完成和日历导入是不同阶段；更新其中一项不能连带把其他阶段改成完成。历史 Anki 迁移脚本不属于日检或周检的自动步骤。

这些文件很大，不要整份读取。日常判断先运行 `python3 _系统/脚本/状态摘要.py`；判断某个来源是否已处理，用 `--find <路径或哈希>` 查完整记录，摘要不能用于去重。

## 结束与验收

有变化时核对学习者归属、原件完整性、来源定位、中英对应、考核状态、内部链接及正式写入回读；涉及日期或 ICS 时再执行日历细则的检查。同步受影响的入口，Wiki 有变化时更新索引并追加日志；有实际产物时写一行[[_系统/交接/说明|交接记录]]。

只报告实际完成的阶段和产物，注明失败、待核与未验证部分。没有实质变化且没有待生成的预习时静默结束；首次生成、实质更新、重要日期变化、首次需本人操作或失败时按现有通知规则处理，已知未变缺口不重复催促。

每日收集与课程周检共用这套分流规则。每周知识蒸馏读取 [[每周蒸馏/说明|周报规则]]，检查已启用模块和进行中项目的真实变化；它不代替网站收集，也不自动重跑全部课程阶段。
