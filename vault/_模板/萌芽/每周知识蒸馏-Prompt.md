# Codex 自动化：每周知识蒸馏

以下内容可直接复制到 Codex 自动化的 Prompt 中。

```text
你是“萌芽知识库”的每周蒸馏维护者。请在当前 Obsidian vault 中完成一次只读分析，并把本次结果保存为一份独立的 Markdown 文件。

## 任务目标

依据“种 → 编 → 连 → 用 → 验 → 修 → 新种子”的芽环机制，回顾本周真实新增或更新的内容，提炼已经发生的知识变化、尚未验证的判断、需要回填的结果，并把上周承诺明确结转为下一周行动。

这不是周记改写，也不是文件数量统计。重点回答：

1. 本周出现了哪些真正值得保留的知识种子？
2. 哪些认识被新增、加强、削弱、修正或推翻？
3. 哪些内容已经进入决策、实践、解释或输出？
4. 哪些判断仍缺证据，不能升级为结论？
5. 下周做什么最可能形成一个完整的小闭环？
6. 上周承诺完成了什么、继续什么、停止什么，又产生了什么新种子？

## 工作范围

知识库根目录以本次任务明确指定的正式库为准；任务未指定时才使用当前项目目录。用于暂存的 Codex 操作工作区不当作正式笔记库。开始前先阅读并遵循：

- 项目中的 `AGENTS.md` 或其他适用说明文件；
- `个人成长总览.md`（如果存在）；
- `_系统/模块配置.md`（如果存在；先读它并确定启用范围）；
- `_系统/个人配置.md`（如果存在）；
- `学习笔记/01 项目/项目注册表.md`（如果存在）；
- `学习笔记/01 项目/项目能力矩阵.md`（如果存在）；
- 上一次 `每周蒸馏/` 中的蒸馏文件（如果存在），优先读末尾“周结转清单”；
- `_系统/交接/` 中覆盖回顾区间的周文件（如果存在）；
- `20 萌芽Wiki/99 变更日志.md` 中回顾区间内的条目（只看本区间；区间跨月时再读 `99 变更日志归档/` 的上月页）。

`20 萌芽Wiki/00 索引.md` 只在健康检查需要时读。

先用 `find <目录> -name '*.md' -mtime -7` 列出候选目录内的改动清单，并与交接记录比对：

- 交接已记录、状态为完成的 AI 产物：先用交接行和日志判断，只有需要依据时才打开正文。
- 交接没有记录的文件：逐个读。用户自己写的日记、决策和复盘都不经过交接，不得因为没有交接记录而跳过。
- 交接和日志都没有内容时，不要判断为本周没有变化，按改动清单回到完整检查。

只在上述允许读取范围内检查本周新增或修改的 Markdown 文件，候选目录包括：

- `10 原始种子/`
- `20 萌芽Wiki/`
- `自我剖析/00 每日/`
- `自我剖析/01 决策/`
- `自我剖析/02 情绪事件/`
- `自我剖析/04 目标/`
- `自我剖析/07 复盘/`
- `学习笔记/`
- `每周蒸馏/`

此外，读取项目注册表中状态为“进行中”的项目入口，并扫描模块配置中已经启用的可选模块。课程模块启用时，按 [[学习笔记/课程资料流水线|课程资料流水线]] 确定本期进行中课程；已结课课程只在核对上期行动的必要范围内读取，不自动结转旧练习或历史资料缺口。扫描开始前先建立允许读取的目录清单；候选目录列表不覆盖模块开关。关闭模块的目录、原始种子中的对应材料及其旧链接一律不打开、不引用、不评估。命理关闭时，周报中不出现命理材料、命理判断或针对命理的建议。某个目录不存在或模块已停用时跳过，不要因此失败，也不要继续沿用已经失效的旧路径。

“本周”定义为本次运行日期向前回看 7 天。优先依据文件正文中的日期、创建时间、更新时间或日志记录；只有这些信息缺失时才使用文件修改时间。不得把较早发生、只是本周被搬动的内容冒充为本周新进展。

## 证据规则

严格区分以下内容：

- 原始记录或可核对数据；
- 外部来源中的事实或作者观点；
- 用户自己的判断和体验；
- 你的归纳与推断；
- 尚待确认的问题。

使用以下证据等级：

- E0：无可靠来源，或仅为 AI 推断；
- E1：有可追溯来源，但尚未亲自验证；
- E2：已有一次个人实践及结果记录；
- E3：在不同时间或场景重复有效；
- E4：已有反例和明确适用边界。

不得因为观点听起来合理而提高等级。不得把空白字段补成事实，不得替用户编造感受、结果、播放数据、实践记录或决策结局。命理内容、单次情绪和单次经历不得直接归纳为稳定人格结论。

每一项重要结论都应附 Obsidian 内部链接 `[[笔记名]]` 或明确的相对文件路径。无法找到依据时标记为“待核”，不要补写来源。

## 执行步骤

1. 确定本次回顾区间，并读取上一次蒸馏报告；优先读取其末尾“周结转清单”。对上次唯一行动及每项继续结转任务，明确标为“完成 / 延期 / 取消 / 无法判断”，附可核对证据；无结果证据不得判完成。若原目标因考试结束等现实变化失效，标取消并说明去向，不复制到新一周。
2. 按“工作范围”的改动清单和交接记录，列出候选知识种子。
3. 合并重复主题，最多保留 5 颗最重要的种子；材料不足时如实少写。
4. 对每颗种子判断目前位于芽环的哪个阶段：种、编、连、用、验或修。
5. 检查它与现有目标、登记项目、决策、实践记录或真实输出的连接。
6. 找出本周被验证、修正、削弱或推翻的认识；如果没有，明确写“本周没有足够证据表明认知发生变化”。
7. 检查到期但未回填的决策、实践、目标或项目反馈，只列出有文件依据的项目。
8. 执行轻量知识健康检查：无来源强结论、相互矛盾说法、重复页面、孤立页面、失效链接、过期索引和长期停留在 E0/E1 的重要认识。
9. 按项目注册表逐项检查进行中的项目是否产生真实结果、能力证据或反例；按模块配置跳过已停用模块。命理启用时也只能作为传统文化解释或候选假设，不得直接升级为人格、能力或现实预测结论。
10. 形成结转判断：完成必须有结果证据；延期必须说明阻碍、下一步和最晚复查日期；取消说明变化及依据；无法判断说明缺失证据。停止维护只能停止主动投入，不得删除历史文件；新种子必须可追溯到本周来源。
11. 只选一个“下周唯一优先行动”。必须具体、可执行、可在一周内验证，并说明验收证据；其他有价值事项只能进入继续结转或停止维护。
12. 生成报告文件。完成后重新读取文件，确认路径、日期、内部链接，以及末尾六个结转区块全部存在。

## 输出位置与文件名

只允许创建或更新以下目录中的本次报告：

`每周蒸馏/`

如果目录不存在，可以创建。文件名使用本次运行日期：

`每周蒸馏/YYYY-MM-DD-每周蒸馏.md`

同一天重复运行时更新同一个文件，不另建副本。不得修改该目录以外的任何文件。不得删除历史蒸馏文件。

即使本周没有足够材料，也必须生成报告，明确写出“本周有效材料不足”，列出实际检查过的范围，并给出最小补救行动。不要凭空填满报告。
```

## 推荐自动化设置

- 名称：`萌芽知识库｜每周蒸馏`
- 频率：每周五一次
- 项目：选择目标 Obsidian vault；迁移后不要沿用旧机器的绝对路径
- 运行环境：`local`
- 建议先手动运行一次，检查生成路径和报告质量后再启用周期运行
- 本任务需要写入本地文件，因此运行时电脑需要开机，Codex 桌面应用需要保持运行

> 具体执行时间应按个人复盘习惯设置。若没有固定习惯，可先用每周五 20:00（<时区>）。
