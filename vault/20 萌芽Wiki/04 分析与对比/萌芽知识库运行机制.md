# 萌芽知识库运行机制

> 人负责投入真实材料、采取行动和确认结果；AI 负责把材料编译成可追溯、可连接、可使用、可验证和可修正的知识。

系统的最终目标不是增加笔记，而是通过个人当前真正需要的项目提升能力，并用现实反馈逐步加深自我理解。项目可以变化，核心证据规则保持不变。总入口见 [[个人成长总览]]，项目清单见 [[项目注册表]]，领域词汇见 [[CONTEXT]]。

## 唯一主循环

`种 → 编 → 连 → 用 → 验 → 修 → 新种子`

1. **种｜捕获**：外部资料原样进入 `10 原始种子/`；个人经历继续记录在自我剖析、学习项目或播客项目中。
2. **编｜提炼**：生成来源摘要，严格区分原文事实、作者观点、用户经验、AI 推断与待核项。
3. **连｜连接**：至少连接一个目标、决策、实践、课程、播客选题或已有概念；无法连接时标记“待连接”。
4. **用｜行动**：必须进入一次判断、练习、解释或真实输出。只有收藏、摘要和链接不算完成迭代。
5. **验｜回填**：记录结果、数据、错题、反例和适用边界，并按 E0–E4 更新证据等级。
6. **修｜更新**：修正旧认识、保留矛盾、合并重复概念并修复索引；不覆盖历史证据。
7. **新种子**：未解决的问题、听众反馈、错题和实践失败进入下一轮。

## 双责任制

| 内容 | 人的责任 | AI 可以做什么 |
| --- | --- | --- |
| 原始资料、感受、决策意图 | 提供并确认真实性 | 只读、整理、提出待确认问题 |
| 来源摘要、概念与分析页 | 审阅关键结论 | 新建或增量更新，必须标明来源 |
| 学习成绩、实践结果、播客数据 | 提供真实结果 | 计算、对比、归纳，不补造空白数据 |
| 个人规则 | 决定是否采纳 | 只有达到 E3 才能建议升级 |

## 证据升级

- **E0**：无可靠来源，或仅为 AI 推断。
- **E1**：有可追溯来源，但尚未亲自验证。
- **E2**：完成过一次真实实践，并留下结果。
- **E3**：在不同时间或场景重复有效。
- **E4**：已经记录反例和明确的适用边界。

观点听起来合理不能提高等级。播放量、分数或一次感受只能成为证据的一部分，不能单独证明因果或形成稳定个人规则。

## 项目驱动，不写死应用场景

任何项目只要能说明目标、交付物、能力、证据和停止条件，就能接入系统。下面是当前使用中的实例，不是框架的固定组成。

### 学校 学习

`课程资料 → 考点 → 练习 → 错题 → 复测 → 修正复习策略`

掌握必须由闭卷作答、错题记录、作业反馈或复测结果证明。

### SRC 学习

`基础知识 → 合法靶场 → 最小证据 → 根因与修复 → 换环境复现 → 报告`

扫描器或 AI 给出的线索不算本人能力；必须在授权边界内独立复现、解释和记录停止条件。

### 自我剖析

`记录 → 假设 → 行动实验 → 结果回填 → 重复验证 → 个人规则`

单次情绪、命理解释或一次经历不能写成稳定人格事实。命理属于外部文化材料，只能提出候选假设；现实记录和反例决定假设是否保留。见 [[命理研究入口]]。

### 播客

`来源与选题 → 稿件 → 制作 → 发布 → 数据与评论 → 复盘 → 下一版选题/表达`

稿件事实回链原始来源；播放表现用于验证选题和表达，不用于证明观点真假。具体规则见 [[播客/迭代说明]]。

所有登记项目通过 [[项目能力矩阵]] 共用能力定义、基线、AI 帮助程度和复测证据。可选模块是否参与维护，由 [[_系统/模块配置|模块配置]] 决定。

## 运行节奏

- **随时**：把新资料和真实问题投入正确入口，不要求立即整理。
- **每周**：挑选 1–3 个最重要的种子，完成轻量 Lint，并产出一份带周结转清单的蒸馏报告。
- **每月**：处理到期回填、重复页面、失效链接和长期停留在 E0/E1 的重要认识；决定下月停止维护什么。

## 完成标准

一次迭代至少要有：可追溯来源、现实连接、一次使用、结果证据、对旧知识的更新，以及一个明确的新问题或停止条件。

规则执行边界以根目录 `AGENTS.md` 为准；本页解释系统为什么这样运行，不替代操作规则。
